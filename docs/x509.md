# Certificate parsing

`stdlib.x509` parses one borrowed DER certificate with `parse-der`, or a
certificate PEM bundle with `parse-pem`. Both take `x509.default-limits` (or a
modified `Limits` value). Results contain a complete owned model or one error;
no certificate, name list or bundle is returned on failure.

Successful `Certificate` values own exact DER bytes. `der.Range` fields locate
the encoded TBS, SPKI, issuer/subject, validity, algorithm identifiers and
extensions. Signature, public-key, serial, identifier and text ranges locate
their exact content bytes. `x509.view` borrows a range from its certificate;
`byte_buf.from-bytes` can copy that view. Range offsets stay valid when the
certificate moves. Keep the owner alive while using a borrowed view.

The parser decodes versions 1–3, positive nonzero serials of at most 20 encoded
octets, names, validity, SPKI, signatures, unique identifiers and the v3
extension sequence. Inner and outer signature AlgorithmIdentifiers must be
byte-identical. Known parameter/key/signature encoding profiles include RSA,
RSA-PSS, P-256 ECDSA and Ed25519. Parsing does not perform cryptography, check
trust or current validity, match a service identity, construct a path, or
advertise support for using these algorithms. RSA-PSS ASN.1 defaults are
retained when omitted; signature policy must decide whether to allow them.

Basic constraints, key usage, extended key usage, subject/authority key
identifiers, subjectAltName and name constraints have decoded fields. Every
extension also retains its OID, critical flag, encoded range and encapsulated
value. Unknown critical extensions remain visible so path validation can
reject them; parsing success never means that all critical extensions are
understood. Unknown noncritical values remain skippable after bounded DER
validation. DNS and other IA5 fields preserve ASCII bytes and case; domain,
wildcard, URI and identity matching policy belongs to consumers.

GeneralName supports rfc822Name, dNSName, URI, iPAddress, registeredID,
otherName, directoryName and ediPartyName. SAN IPs use `stdlib.net.ip.IpAddr`
with exactly 4/16 bytes; IP subtrees use typed address and mask values from
exactly 8/32 bytes. Name constraints require the RFC 5280 default minimum
(omitted zero) and absent maximum. The x400Address alternative is unsupported
and fails the whole certificate with `UnsupportedGeneralName(3)` and its byte
offset. It never produces a partial SAN/constraint list. Malformed DER and
invalid supported CHOICE structures have malformed-encoding errors. The
unsupported X.400 schema is not a path-validation capability.

`stdlib.asn1_der` validates the universal types used by the certificate
profile, canonical tags/definite lengths, INTEGERs, BOOLEANs, BIT STRING
padding, OIDs, character encodings, times, SET order and exact consumption.
Other universal types produce `UnsupportedType` rather than a success with
unchecked contents. Known schemas enforce field ordering, omitted DEFAULTs
and uniqueness. All failures contain categories/offsets, never input bytes.

`stdlib.x509_time` accepts exactly UTCTime `YYMMDDHHMMSSZ` and GeneralizedTime
`YYYYMMDDHHMMSSZ`. It checks Gregorian dates, rejects leap seconds, offsets,
fractions and missing seconds, and returns signed epoch milliseconds without
host locale/timezone conversion. UTCTime maps 50–99 to 1950–1999 and 00–49 to
2000–2049. The bounded year domain 0001–9999 fits the signed result exactly.

Default DER limits are 1 MiB per certificate, 32 nested values and 16,384
nodes. Encapsulated extension/key/signature DER shares the certificate's node
budget and includes enclosing values in its depth budget. The hard depth
ceiling is 64, implemented with a fixed stack. Model limits allow 128
extensions and 1,024 entries per name/purpose/subtree collection. Lengths and
counts are checked before attacker-sized allocation/copy; schema processing
uses checked source ranges. Duplicate OID checks are quadratic within the
configured collection caps; increase those caps deliberately.

PEM defaults allow 16 MiB of input, 128 certificates, 1 MiB decoded per block
and 8 MiB decoded in total. The certificate loader applies the stricter of
the DER and PEM per-certificate caps before base64 allocation. The PEM layer
accepts exact case-sensitive matching `CERTIFICATE` boundary lines, CR/LF/CRLF
newlines, optional ASCII whitespace around markers, and SP/HT/VT/FF/CR/LF in
payloads. Other payload bytes reach the existing canonical padded standard
base64 decoder unchanged. Explanatory lines outside blocks are ignored; a
trimmed line starting with five hyphens must be a valid boundary. Other labels,
nested/unmatched markers, empty blocks and incomplete bundles fail.

DER errors use original DER offsets. Standalone PEM errors use original PEM
offsets, including mapped base64 errors. `parse-pem` returns `LoadError`:
`certificate-index=-1` denotes a PEM framing/base64 error; otherwise it names
the zero-based block, `error.offset` is within decoded DER, and `source`
locates the original envelope. This avoids pretending a decoded offset is a
byte location in its base64 source.

The parser follows [RFC 5280](https://www.rfc-editor.org/rfc/rfc5280),
[RFC 7468](https://www.rfc-editor.org/rfc/rfc7468) and the supported DER
encoding rules of [X.690](https://www.itu.int/rec/T-REC-X.690-202102-I/en).
The focused fixture/corpus test is `stdlib/tests/x509_api.tl`.
